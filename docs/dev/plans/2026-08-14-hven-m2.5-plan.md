### Task 1 — engine compile-cost reduction (hven) [AMENDED]

As originally chartered (the M2 plan's excised Task 7: TU splitting),
this task refuted its own premise by measurement before any split
shipped: hven's compile cost is a per-TU header floor, not file length
(the shared include block alone costs ~3 s; a 39-line TU costs 42% of
the 3722-line engine TU), mechanical splits measured +61% to +187% CPU
and were slower at every parallelism, and with LTO off every new TU
boundary is a de-inlining hazard on the solver hot path. Owner accepted
the refutation; the split is dead. Evidence: the Task 1 report.

The amended deliverable, owner-approved: a precompiled header over the
engine's shared include block, mirroring tycho's own PCH conventions
(clang -fno-pch-timestamp; ccache pch_external_checksum guidance
documented for developers). Measured on this box: −29% on the engine TU,
−32% on globalization, ~−18% total library compile CPU — with the PCH
object BYTE-IDENTICAL (SHA256) to the non-PCH object, so runtime
neutrality and rig-row invariance hold by construction.
Gate: the byte-identity object check repeated on Linux (and asserted in
CI where feasible); hven suite Release+Debug; independence gate empty;
CI x3 (open a draft PR m2.5 → main — the workflow does not fire on bare
branch pushes); build-time before/after recorded; ccache developer note
added to hven docs.
